## Устройство проекта

`scripts/prepare.py` проверяет дамп и преобразует ELF в образ загрузчика.
`link_libc.py` и `link_modules.py` связывают модули PS4; `patches.py` создаёт
отдельный набор патчей. `scripts/mods.py` создаёт временное представление игры
с модами. Исходные файлы игры не перезаписываются.

`src/probe.c` загружает образ и исполняет оригинальный x86-64-код.
`src/runtime*.c` реализуют системные функции PS4. Гостевые функции используют
System V ABI на хосте Win64. Windows-часть обеспечивает TLS в TEB, полностью
выделенные стеки, адресное пространство гостя, общую память, vectored exceptions
и восстановление через `bb_setjmp`/`bb_longjmp` без SEH-раскрутки гостевых кадров.

`gpu/shadps4/` содержит графическое ядро и трансляцию шейдеров; `gpu/shim/`
связывает его с HLE. Командный процессор передаёт работу планировщику Vulkan;
кэши буферов и текстур согласуют копии CPU/GPU. Presenter и temporal upscaler
формируют вывод и апскейлинг. На Windows библиотека GPU статическая.

`run.py` отвечает за подготовку, запуск, логи и перезапуск Windows.
`launcher/bbport_launcher_win.py` — интерфейс Tk.
`packaging/windows/` собирает пакет и дополнительный мост DLSS.

## Перенесённые изменения

- Планировщик с несколькими работниками и сегментами команд, уточнённые
  ожидания копирования, сохранение командных буферов при submit, отложенное
  освобождение ресурсов. Windows-ветки DLSS и дампа кадров сохранены.
- Исправления освобождения VRAM и отслеживания записей. Backing-чтения обходят
  гостевую защиту страниц; малые записи fence не сохраняют байты повторно.
- Исправления TAA, векторов движения, реактивной маски, линейного цвета FSR 4,
  DoF и кэша шейдеров. Кэш заменяется целиком после записи временного файла.
- Рендерер FSR 4.1.1/FP8 с проверками GPU. Windows-лаунчер выбирает каталог
  `fsr4_411` и проверяет набор для разрешения/пресета. Пакет включает каталог
  при наличии. Неподдерживаемый GPU использует переход upstream на FSR 3.1.
- Контроллер по GUID/имени, назначения `key.*`/`pad.*`, страница управления,
  идентификаторы и время удержания касаний. Удерживаемые кнопки, триггеры и
  касания после меню скрываются до отпускания.
- Проверка конкретного расшифрованного `eboot.bin` CUSA03173 1.09 и требований
  CPU. Одного имени папки или версии в SFO недостаточно.
- Новые настройки preupload, копий GPU-буферов, GPU write twins и vblank.
  Сохранение консоли и покадрового CSV в `logs/`.

## Адаптации Windows

- Сохранены pagefile-backed section и placeholder mappings вместо memfd.
  Windows-запуск отключает `BB_PC_MODEL`, `BB_GUEST_IN_PLACE`,
  `BB_GUEST_GPU_MEMORY`, `BB_UFFD`; рендерер также проверяет доступность backend.
- Linux dma-buf и экспериментальные ELF/SysV hooks диагностики аллокатора,
  освобождений и GNM не устанавливаются. Общие интерфейсы реализованы в
  `gpu/shim/bbport_diagnostics_win.cpp`; штатное отслеживание Windows сохранено.
- `ReadProcessMemory`, Windows CONTEXT и CaptureStackBackTrace заменяют
  Linux-средства диагностики. RSS берётся из Windows API.
- Настройки заменяются через `filesystem::rename`: CRT `rename` на Windows
  не заменяет существующий файл.
- Все части статического рендерера используют Win32 layout Vulkan-Hpp.
  GPU-тесты сохраняют ABI библиотеки и используют активные проверки отдельно:
  `-UNDEBUG` меняет layout диспетчера в используемом Vulkan-Hpp.
- Исправлены 64-битные HANDLE при перезапуске и подключении stdout, а также
  распознавание hardlink при смешанных разделителях Windows/MSYS2.
- NGX завершается до уничтожения Vulkan-device: прежний вызов только из atexit
  обращался к уже уничтоженному device и приводил к сбою внутри драйвера NVIDIA.
- Обновления лаунчера направлены в `AwesomeObserver/bloodborne_pc`.
  Пользовательские логи и ассеты FSR 4.1.1 сохраняются при обновлении.

## Воспроизводимая проверка

Из MSYS2 CLANG64 выполните `bash build.sh --test`.
Для нестандартной установки MSYS2 задайте `MSYS2_ROOT`.
Локальный toolchain в `out/msys64` также находится автоматически.
После сборки подмодуль `fsr-vulkan` содержит два ожидаемых изменения из
`gpu/patches/fsr-vulkan/`: `build.sh` применяет эти сохранённые патчи автоматически.
Проверено с Clang 22.1.8, SDL 3.4.18, Vulkan headers 1.4.363,
FFmpeg 9.0.2 на Windows.

- Собраны `bb-probe.exe`, `bb-gpu-capabilities.exe`, `bb-play.exe`.
- Собран `bbport_dlss.dll` через MSVC 19.44 и официальный NVIDIA DLSS SDK
  `3749594`; проверены загрузка/инициализация NGX и завершение с подключёнными DLL.
- 14/14 CTest: полный запуск Windows-загрузчика, скрытого SDL-окна, swapchain,
  presenter и GPU-кэшей с синтетическим гостевым кодом; Vulkan submit/readback,
  история движения, трансляция шейдеров,
  композиция UI, настройки, масштабирование сцены, TAA, векторы камеры,
  выбор апскейлера, HLE runtime, семафоры, виртуальный SDL-контроллер, AppContent.
  Startup-тест использует путь с пробелами и кириллицей. При наличии собранного
  DLSS-моста `build.sh --test` автоматически подключает его к GPU-тестам.
- Четыре сгенерированных SPIR-V шейдера движения прошли `spirv-val` для Vulkan 1.3.
- 110 Python-тестов: 93 успешно, 17 пропущены. Пропуски относятся к Linux
  run.sh/AppImage и созданию symlink без соответствующего права Windows.
  Проверены синтетические гостевые образы, ошибки загрузчика, подготовка,
  патчи, моды, запуск/перезапуск и настоящие Tk-элементы страницы управления.
- Runtime-тест проверяет общие aliases, backing-чтения/записи при запрещённом
  гостевом доступе, малые записи разных размеров/выравниваний, чтение нулей
  и отказ записи после unmap.

## Границы проверки

Дамп для длительного игрового прогона пока не предоставлен. Проверки не
подтверждают прохождение игры или отсутствие сбоев во всех локациях и драйверах.
FSR 4/4.1.1 INT8/FP8 требует подходящего GPU и пользовательских ассетов:
исполнение моделей и качество изображения в игре здесь не проверены.
Проверен переход на FSR 3.1 при отсутствии необходимых возможностей.

Извлечение ассетов из DLL (`tools/fsr4cap/build_assets.sh`) остаётся инструментом
Linux/Proton. На Windows выбирается подготовленный каталог. Proton и
экспериментальная Linux-модель памяти не являются зависимостями Windows-пакета.

Перед выпуском нужен прогон CUSA03173 1.09: новая игра/загрузка сохранения,
жесты, ввод имени, смена разрешения с перезапуском, полноэкранный режим,
несколько локаций и длительная сессия с включённым сохранением логов.
