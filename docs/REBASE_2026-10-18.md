# Windows 1.9.1 integration - 2026-10-18

Upstream base: `b4dcc82` (Windows 1.9.1). Previous FG/Reflex head: `948a870`;
previous NR head: `735f966`. The earlier branches and release remain recoverable.

Retained upstream changes:

- The shadPS4 0.20.1 GPU/shader layer (`087bbf3`).
- The 1.9.1 index-buffer correction for stretched polygons (`5012c6f`).
- Guest-memory VRAM reserve and restored texture placement (`5f65e2d`), replacing
  the 1.9 texture-spill policy that reduced performance after area loads.
- Reserved guest-memory fallback with commit-on-map (`7c9ebcb`).
- Expanded mod layouts and visible discovery failures (`dd2314e`).
- The remaining 1.9/1.9.1 memory, rendering and compatibility changes.

The upstream FG implementation and follow-ups (`026f8ff`, `aabd7f7`, `389124d`,
`3093990`) are explicitly reversed before replaying the local integration. This
retains the local DLSS/FSR providers, GPU-completion timing/deadlines, expired-slot
skipping, resource leases, FSR retirement patches, Reflex attribution and adaptive
source gate. The native source/presentation counter remains the local implementation.
The upstream automatic FIFO source cap and refresh-fitting FG controls are absent.

The integration is replayed as a refreshed, consolidated patch over this base,
with prior contributor attribution preserved. Compatibility adaptations retain
upstream's component-swizzle representation and four-semaphore wait array. The
relocated GNM flip-patching helper carries the content frame ID, including the
new request-flip/submit-done path; duplicate helpers are not retained.

The index-buffer, buffer-cache, texture-placement, guest-memory and mod-discovery
fix files were compared byte-for-byte with upstream 1.9.1. The local FG provider,
Reflex core, timing policy, image lease and NVIDIA bridge sources were compared
byte-for-byte with the prior FG head. Shared glue changes only where the newer
GPU API requires it. Compiler source-prefix mapping keeps local build paths out
of distributed diagnostic strings.

FG/Reflex validation before adding NR: CLANG64 RelWithDebInfo build; 69 focused
Python checks (one optional skip); nine native timing/settings/ownership suites;
the guarded bridge rejection test; two FG shader/SPIR-V checks; and the ABI-2
adapter table pass. Fifteen mod tests pass. The symlink-rejection test cannot run
with this Windows account's permissions (WinError 1314); it is not reported as a
pass. NR and packaged-launcher validation are recorded with the final build.

No GPU gameplay, frame-pacing, online or endurance measurements have been run on
this 1.9.1 integration. Previous measurements identify their earlier executables
and must not be attributed to this build.
